# 设计文档：地图与图形程序的表达方式

本文说明 Little Explorer 的核心设计——一套「地图」与「图形程序」的表达方式，屏幕版与纸质版共用同一套语义。

## 1. 整体思路

把编程拆成两件都是"画画"的事：

- **画地图** = 设计关卡（在网格上贴元素）
- **画程序** = 写解法（把图形积木拼起来）

底层是一个 **网格世界（grid world）**：角色站在格子上，按程序逐格行动。这与 Swift Playgrounds 的 *Learn to Code* 同构，但连"关卡设计"也图形化了。

## 2. 地图的表达方式（两层）

| 层 | 作用 | 小朋友看到的 |
|---|---|---|
| 视觉层 | 自由涂鸦 + 选元素贴纸 | 在格子画板上贴「贴纸」拼出地图 |
| 数据层 | 程序读取执行 | 自动转成 `坐标 + 元素类型 + 状态` |

### 2.1 元素词汇表

| 元素 | 含义 | 状态 |
|---|---|---|
| 角色 Hero | 小探险家，有朝向 | 位置 + 朝向 |
| 宝石 Gem | 收集目标 | 存在 / 已收 |
| 开关 Switch | 踩一下切换 | 开 / 关 |
| 传送门 Portal | 成对（A↔A），踩上瞬移 | 成对坐标 |
| 墙 Wall | 不可通行 | — |
| 终点 Goal | 到达即胜利 | — |
| 起点 Start | 角色出发处 | 初始位置 |

### 2.2 传送门规则

- 地图上有若干对传送门（用相同字母/颜色配对，如 A↔A）。
- 角色移动落在一张传送门格上时，瞬移到其配对门，朝向保留（可配置）。

## 3. 图形程序的表达方式（三类积木）

| 类型 | 积木 | 语义 |
|---|---|---|
| 动作块 | 前进 / 左转 / 右转 / 收集宝石 / 切换开关 / 跳 | 顺序执行，每个 = 地图上一格动作 |
| 控制块 | 重复 N 次 / 如果·否则如果·否则 | 带插槽容纳子块；决定循环与分支 |
| 变量 | 变量名贴纸 + 变量值面板 | 运行时用铅笔填值、改写 |

### 3.1 动作块

- **前进**：朝当前朝向移动一格（遇墙/边界则不动，标记错误）
- **左转 / 右转**：朝向旋转 90°
- **收集宝石**：若脚下是宝石则移除
- **切换开关**：若脚下是开关则翻转开/关
- **跳**：跳过前方一格（越过墙）

### 3.2 循环：重复 N 次

```
重复 [N] 次
  └─ （贴要重复的动作块）
结束重复
```

### 3.3 分支：如果 · 否则如果 · 否则（else-if 链）

用「分支卡」上下拼贴成链：一张「如果」打头，中间可叠任意张「否则如果」，最后用「否则」收尾。条件处贴条件药丸（前方有宝石 / 前方有墙 / 开关开着 / 脚下是宝石 / 在传送门上）。

```
如果 [条件]
  就做 → 动作块
否则如果 [条件]
  就做 → 动作块
否则
  就做 → 动作块
```

### 3.4 变量

- **变量名贴纸**：手写变量名，可贴到循环框「重复 __ 次」旁引用它。
- **变量值面板**：多行 `变量名 ____ = 数值 ____`，用铅笔填写；虚拟运行时随程序擦改写（例如循环计数 `count: 3→2→1→0`）。

## 4. 执行语义

- 程序在地图上「运行」：角色按积木顺序执行，地图上实时动画（屏幕版）或手动移动（纸质版）。
- 每个**动作块** = 地图上的一次动作；**循环 / 分支块**决定重复与分支。
- **胜利条件**（可配置）：收齐所有宝石 **且** 拨开所有开关 **且** 到达终点。

## 5. 给小朋友的 4 步工作流

1. **画地图**：贴纸放 Gem / Switch / Portal / 墙 / 终点
2. **拼程序**：拖图形块组成解法（顺序 → 循环 → 分支 → 变量）
3. **运行**：看小人按程序走，收集 / 传送 / 到终点
4. **调试**：不对就改图或改程序（对比"正常/异常"定位问题）
