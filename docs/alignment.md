# 对齐分析：小小探险家 ↔ Swift Playgrounds「学习编程」

> 目的：对照 Apple 官方 **Swift Playgrounds → 学习编程 1 / 2 / 3（Learn to Code）** 的课程结构与编程要素，把我们「小小探险家」实物 + 网页套件逐章对齐，标出 **已覆盖 / 部分覆盖 / 缺失**，并给出补齐建议。
> 说明：Apple 的课程章节编号与文件夹名会随版本微调，但「命令 → 函数与循环 → 条件 → 条件循环 → 算法 → 变量 → 类型/参数/数组」的主线长期稳定。

## 3. 逐章对齐矩阵

| Swift 章节 | 编程要素 | 我们的对应 | 状态 |
|-----------|----------|-----------|------|
| L0 入门 | 运行 / 角色 | 网页版「运行 + 胜利检查」；纸版手指/棋子当角色 | ✅ 已覆盖（纸版靠家长引导） |
| L1 命令/序列 | 单命令 + 顺序 | 6 个动作块 + 按序摆放 = 序列 | ✅ 已覆盖 |
| L2 调试 | 单步 / 观察 | 网页版单步动画 + 胜利检查可当调试；纸版无单步 | ⚠️ 部分（纸版靠肉眼） |
| L3 函数 + for | `func` + `for` | 循环框「重复 N 次」= for ✅；**缺函数 `func`** | ⚠️ 循环已覆盖，**函数缺失** |
| L4 条件代码 | `if/else if/else` + 布尔 + 逻辑符 | 分支卡（如果/否则如果/否则）✅；条件药丸 5 种部分 ✅；**缺逻辑运算符 且/或/非** | ⚠️ 分支已覆盖，**逻辑运算缺失** |
| L5 While 循环 | `while` | **缺「当…时 重复」** | ❌ 缺失 |
| L6 算法 | 组合解题 | 纸版自由组合，天然支持 | ✅ 已覆盖 |
| L7 变量 | `var` / `let` / `+=` | 变量贴纸 + 值面板 | ✅ 已覆盖 |
| L8 类型 | Int/Bool/String | 隐式（数值/布尔），不做块 | ❌ 纸版不做（可接受） |
| L9 参数 | 函数传参 | **缺（函数都缺失）** | ❌ 缺失 |
| L10 数组 | 集合 | **缺** | ❌ 缺失（进阶） |
| L3 综合 / 学习编程 3 | 坐标/事件 | 大幅超出纸版范围 | ❌ 进阶（可作网页版扩展） |

**覆盖小结**：学习编程 1 的「命令 / 序列 / 循环 / 分支 / 变量 / 算法」已基本覆盖；缺口集中在 **函数、条件循环（while）、逻辑运算符** 三处，以及 L2 的「调试单步」在纸版较弱。

## 5. 语义差异需修正（让对齐更严谨）

1. **开关条件方向**：Swift 的 `isOnClosedSwitch` 指「脚下是**关闭的**开关」（需要打开）。我们目前只有「开关开着」。对齐建议：补充「开关关着」药丸，与 `isOnClosedSwitch` 对齐；保留「开关开着」作为状态查询。
2. **前方 vs 脚下**：我们的「前方有宝石 / 前方有墙」是「前方」视角，Swift 的 `isOnGem` 是「脚下」视角。两者都保留（「脚下是宝石」已对应 `isOnGem`），「前方有墙」对应 `isBlocked`，语义合理。

## 6. 为对齐需新增的元素（建议）

优先级按「离当前进度最近、性价比最高」排序：

| 优先级 | 新增元素 | 对齐章节 | 设计建议 |
|--------|----------|----------|----------|
| **P0** | **函数卡**：`函数名____` + 函数体（贴动作）+ `调用____` 贴纸 | L3 `func` | 一张定义卡（名字 + 身体区），若干「调用」小贴纸引用它 |
| **P0** | **条件循环框**：`当 [贴条件] 时 重复` + 结束 | L5 `while` | 大框样式同循环框，顶部条件槽贴药丸 |
| **P1** | **逻辑运算符贴纸**：且 / 或 / 非 | L4 `&&` `\|\|` `!` | 小药丸，把多个条件串成组合条件（如「脚下是宝石 且 前方有墙」） |
| **P1** | **扩展条件药丸**：开关关着 / 左侧有墙 / 前方受阻 | L4 | 补 `isOnClosedSwitch` 对齐，丰富分支 |
| **P2** | 类型 / 参数 / 数组 | L8–L10 | **纸版不做**；标注为「网页版进阶 / 学习编程 2 后半」，保持诚实 |

## 7. 我们的独特优势（Swift 没有）

- **传送门 A**：自定义地图元素，Swift 固定关卡没有，增强空间推理。
- **自由画地图**：Swift 关卡是预设的；我们让孩子先画地图（设初值），再写程序，因果更直观。
- **低屏幕时间**：纸版拼贴 + 手指/棋子执行，天然减少看屏。
- **跳 + 墙**：完整对应 Swift 的 `jump()` 越过 block 机制。
